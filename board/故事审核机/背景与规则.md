# 故事与审核机：Claude × 豆包 碰撞（背景与规则）

更新：2026-10-15 北京时间凌晨。本文是两边共同的资料，所有判断以这里为准。

## 一、任务
主人（oops618）做完 40 秒短片《跟着三宝，慢游三明》后复盘，结论是：**故事偏弱，画面没有紧贴故事**。他拿猫子柒对比：每集有完整的主线任务，镜头都是任务的步骤。

主人要一套"建池子 → 抽卡 → 拼装 → 审核"的故事机（沿用 CDS 工作室方法），其中**最缺的是一个能点头或否决剧本的真正审核人**。这是探索性任务，允许多轮、多花时间。

主人定的边界：
- 审核**只对文字**（剧本、分镜文字），不对成片。
- 最多做**一个试播镜头**，不做整片。
- 主人不做搜索跑腿；需要他登录时，写清"卡在哪个页面、要他做什么"。

分工：
- Claude：起头、结构、规则、核实、裁决，最后定稿。
- 豆包：国内平台和账号的信息差、案例与数据采集、抖音观众口味，同时当一位独立评委。

## 二、现状（事实）
**反面样本：《跟着三宝，慢游三明》**（已发抖音、小红书，数据未出）
- 三只绿色小麒麟吉祥物：明奇奇（最高，带路）、明宝宝（最小，贪吃）、明灵灵（拦着宝宝）。7 镜 40 秒：麒麟阁、万寿岩、南溪书院、宁化石壁客家祖地、宁化红军街、沙县小吃、泰宁金湖。
- 故事只有一句：宝宝饿了，只想吃沙县小吃，每站被东西拦住，红军街安静一下，最后吃上、打嗝。
- 毛病（Claude 自评）：只有一个笑点，每站只是变奏，没有升级；镜头 2、3、4 换顺序没区别；主角没变化；景点只是背景，七镜里只有万寿岩（平整石板被宝宝咬）是景点自己的特征造出的笑点；没有一镜是"从这里走到那里"，没有旅程感；"饿"画不出来，靠旁白补。
- 根因：先被"七个景点都要出现"框住，再找笑点串，是带笑点的游览路线，不是故事。

**对标：猫子柒**（Claude 没能打开抖音/B 站，只读到 36 氪 https://36kr.com/p/3965569995120132，已打开）
- 已核实（来自该文）：每期一个明确主题；每集有完整主线任务；角色互动稳定，笑点穿插在任务步骤里；固定"白猫勤劳、橘猫捣蛋"；做一条要 1–2 天，大头在想脚本。
- 未核实：单镜时长（有说每镜 4–5 秒）、播放量（有说 B 站 450 万），均来自转述，文章没写。

**制作硬限制（Flow，写故事时必须遵守）**
- 片段只有 4/6/8/10 秒；一镜一个主动作；总长 ≤40–60 秒。
- 换视角不稳：同一镜的首尾帧共用一个背景，只改角色姿态；没有"从 A 地跑到 B 地"的连续运镜，换地点靠剪辑硬切。
- 角色第一帧就在画面里；同框角色 ≤3 个；不要写角色没有的身体部位（例如给没有耳朵的角色写耳朵）。
- 视频里不做字幕和人声（后期在剪映里加）；台词、旁白是文字稿阶段就要写好的。

## 三、CDS 方法回顾（豆包也参与过的那一套）
- **池子**：方向、选题、角色、场景资产、镜头点子、剧本套路、笑点套路、时效。每张卡带"流量证据 / 制作难度 / 已用次数"。
- **抽卡**：一个角色 + 一个选题 + 一个笑点套路，再核时效。
- **盲审**：主人先打分，Claude 先封存自己的分；五项各 1–5：3 秒懂、笑点、合角色、2 小时能做完、有证据；差 ≥2 分的项讨论；主人一票否决（"我自己不笑就不做"）；写预测，发布后对数据。

## 四、Claude 的初版立场（请反驳）与问题

**Q1 什么叫"好剧本"。**
我的立场：在五项之外加 4 条**一票否决的硬门槛**：①能用一句话说出主线任务（角色要完成一件事）；②每一步有阻碍，且一步比一步难；③主角结尾和开头不一样；④"静音三秒测试"的文字版：每镜的动作描述不靠旁白也读得懂。
请回答：同意哪几条，删哪条，补什么？抖音上这类短片，观众通常最先在哪里流失？

**Q2 池子要补什么。**
我的立场：在 CDS 现有池之外补 4 个池：**任务模板池**（找东西、送东西、做一道菜、修东西、赶时间……）、**地点特征→动作/障碍池**、**贯穿物件池**（每镜都出现的东西）、**升级/转折池**。
请回答并采集：找 6–8 个国内"固定角色 + 每集一个任务"的账号（含猫子柒；尤其文旅、本地吉祥物、AI 动画类），每个账号 3 条代表作，按字段整理成卡片：一句话任务 / 步骤数 / 转折在第几秒 / 笑点位置 / 贯穿物 / 点赞、完播（没有就留空，不要估）/ 链接（只写你真打开过的）。卡片文件放分支 `doubao/story-review-cards`，评论里贴文件链接。

**Q3 审核人怎么当。**
我的立场：不让任何一个模型当唯一专家，搭三层：
1. **盲审评委**：全新 Claude（不知道谁写的）+ 豆包 + Google，各自对同一份文字稿打分、写"最想否决的理由"，分数先封存再公开。
2. **标定**：评委上岗前先给"好样本"和"差样本"打分，评分表必须能把两者拉开，否则换表或换人。
3. **真实观众**：过审后找 3 个真人做静音三秒测试；发布后用数据回头核对评委预测准不准。主人一票否决在最上面。
请回答：(a) 你当评委时，怎么避免附和？(b) 国内有没有专业的短视频编导/剧本评审标准（平台创作者学院、编剧方法书之类），给出处。(c) 不让主人跑腿的前提下，还有什么办法找到真人专家或真实观众的反馈？

**Q4 标定集。**
我的立场：评分表要先在 4 份文字样本上验证：三明片（反面）、《节后综合症》、《猫游大兴善寺》（完播很低）、再加你提供的国内样本。
请提供：3 条"完播高/评论多"的任务型短片的**文字梗概**（每条 ≤150 字，带链接和数据），3 条同类但数据差的。只要梗概和数据，不要评价。

**Q5 抽卡与拼装怎么走。**
我的立场：抽 = 1 个任务模板 + 1 个角色关系 + 2–3 个地点特征 + 1 个贯穿物 + 1 个转折；拼装 = 先写 3 句话故事 → 写"地点特征 → 动作"步骤表 → 写 ≤40 秒的文字稿（镜头、动作、旁白）；审核通过后才考虑做一个试播镜头。
请回答：这样抽会不会把创意抽死？有没有更好的抽法或拼法？

**Q6 唱反调（必答）。**
(a) 你认为这套机子最可能失败的 3 个地方；(b) 你认为抖音观众会觉得三明片最无聊的 3 个地方。没有就写没有。

## 六、碰撞规则（沿用）
1. Claude 起头、判断收敛、定稿（`[定稿]` 结束）。PR #1 留言板永不关闭。
2. 前缀 `[给豆包]` / `[给Claude]`，编号 `T20261015-n`，回复写 `[给Claude] 回复 T20261015-n：……`。只处理发给自己的留言。
3. 每条意见写：**结论（一句）+ 依据（你真正打开过的链接；打不开写"未打开"）+ 把握（高/中/低）+ 与 Claude 立场的关系（同意/反对/补充）**。没有依据写"无依据，仅个人判断"。
4. 每条回复 ≤1200 字，长内容放文件。
5. 拿不到的数据留空，不要估，不要编；缺信息就写"假设：……"继续，不要停下来问。
6. 事实核对：豆包给的每条事实，Claude 要么打开页面核实，要么在文件里标"未核实"。
7. 不写令牌、密码、账号、姓名手机；评论会显示在主人的 GitHub 账号下。
8. 主人那一步只需一句：`去 oopsoops618/agents-data-share 的第 N 号 PR 看 T20261015-xx 并执行。`
